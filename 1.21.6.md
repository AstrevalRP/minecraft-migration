# 1.21.6

## Rendu personnalisé dans le monde — mixin cassé

### Problème

Injecter dans `LevelRenderer.renderLevel()` avec `@At("TAIL")` et appeler `buf.endBatch()` **provoque un écran noir** en 1.21.6. Le pipeline de rendu a changé de façon incompatible.

### Solution

Utiliser l'event Fabric API `WorldRenderEvents.LAST` à la place :

```java
// Dans l'initialiseur client (implémentant ClientModInitializer)
WorldRenderEvents.LAST.register(context -> {
    float pt = context.tickCounter().getGameTimeDeltaPartialTick(true);
    MyRenderer.render(
        context.matrixStack(),
        (MultiBufferSource.BufferSource) context.consumers(),
        context.frustum(),
        pt
    );
});
```

API `WorldRenderContext` utile :

| Méthode | Type retourné | Usage |
|---|---|---|
| `matrixStack()` | `PoseStack` | transformations de rendu |
| `frustum()` | `Frustum` | culling de visibilité |
| `consumers()` | `MultiBufferSource` | accès aux buffers de rendu |
| `tickCounter()` | `TickRateManager.TickCounter` | partial tick pour l'interpolation |

Le mixin sur `WorldRendererMixin` peut être supprimé entièrement.

## `CustomRecipe` — méthodes supprimées ou modifiées

### `canCraftInDimensions()` supprimée

La méthode `canCraftInDimensions(int width, int height)` n'existe plus dans `CustomRecipe`. Toute implémentation est du code mort après la migration.

### `placementInfo()` retourne `NOT_PLACEABLE`

`CustomRecipe.placementInfo()` retourne désormais `RecipePlacementInfo.NOT_PLACEABLE` par défaut. Cela signifie que la recette n'apparaît pas dans le livre de recettes. Cela **n'affecte pas** le craft réel : `RecipeMap.getRecipesFor()` appelle uniquement `matches()` pour trouver les recettes applicables.

### `isSpecial()` retourne `true`

`CustomRecipe.isSpecial()` retourne `true`, ce qui a pour effet secondaire que `RecipeCraftingHolder.setRecipeUsed()` retourne `true` sans vérifier la contrainte `limitedCrafting`. Le craft fonctionne donc normalement même avec le mode de craft limité activé.
