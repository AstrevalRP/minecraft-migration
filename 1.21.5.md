# 1.21.5

## Renommage des dossiers de données

Les dossiers de ressources dans `data/<namespace>/` suivent désormais des noms au singulier.

| Ancien nom | Nouveau nom |
|---|---|
| `recipes/` | `recipe/` |
| `loot_tables/` | `loot_table/` |

> Ces dossiers étaient déjà renommés en 1.20.2 côté vanilla pour `advancements/` → `advancement/` et `tags/items/` → `tags/item/`. La même logique s'applique ici.

Le jeu ne charge **pas** les ressources depuis les anciens noms. Le craft ou le loot table sera silencieusement ignoré sans message d'erreur clair.

## Nouveau format JSON des recettes

### Ingrédients

Avant (≤ 1.21.4) :
```json
"key": {
  "W": { "tag": "minecraft:planks" },
  "L": { "item": "locks:wood_lock_mechanism" }
}
```

Après (≥ 1.21.5) :
```json
"key": {
  "W": "#minecraft:planks",
  "L": "locks:wood_lock_mechanism"
}
```

- Les tags s'écrivent `"#namespace:path"` (chaîne préfixée `#`)
- Les items s'écrivent `"namespace:path"` (chaîne simple)

### Résultat

Avant :
```json
"result": { "item": "locks:iron_key", "count": 1 }
```

Après :
```json
"result": { "id": "locks:iron_key", "count": 1 }
```

Le champ `"item"` est remplacé par `"id"`.

### Smithing transform

Les champs `template`, `base`, `addition` et `result` acceptent maintenant des chaînes simples au lieu d'objets :

Avant :
```json
"template": { "item": "minecraft:netherite_upgrade_smithing_template" },
"base": { "tag": "minecraft:iron_tool" },
"addition": { "item": "minecraft:netherite_ingot" },
"result": { "id": "minecraft:netherite_sword" }
```

Après :
```json
"template": "minecraft:netherite_upgrade_smithing_template",
"base": "#minecraft:iron_tool",
"addition": "minecraft:netherite_ingot",
"result": "minecraft:netherite_sword"
```

### Symptômes si le format n'est pas mis à jour

Les recettes en ancien format produisent des erreurs de parse dans les logs (type `JsonSyntaxException` ou `IllegalArgumentException`) et ne sont pas chargées. La table de craft affiche un résultat vide.
